# 조건문

작업 디렉터리는 `~/lab/ex06`입니다(문제 1의 1-1에서 만든 `ansible.cfg`를 그대로 씁니다).

**2-1.** `ansible_facts['distribution']`과 `ansible_facts['distribution_major_version']`을 조건으로, Ubuntu 24 계열에서만 실행되는 작업과 Debian 12 계열에서만 실행되는 작업을 각각 `when` 목록형으로 `conditions.yml`에 작성하세요.

**2-2.** `is match`와 `is search` 테스트를 이용해 호스트명 문자열이 `web-`로 시작하는지, 그리고 안에 노드 번호 패턴(숫자)이 포함돼 있는지 각각 확인하는 작업을 같은 파일에 추가하세요.

**2-3.** 임의의 버전 문자열 변수(`app_version: "3.10.2"`)를 만들어, `3.9` 이상인지 `is version(...)` 테스트로 확인하는 작업을 추가하세요.

**2-4.** `register`한 명령 결과에 대해 `is failed`, `is succeeded` 테스트를 사용하는 작업을 추가하세요 (`ignore_errors` 필요, 존재하지 않는 파일을 확인하는 명령을 쓰면 됩니다).

— `~/lab/ex06/conditions.yml`
```yaml
---
- name: Conditions practice
  hosts: ansible-node1
  vars:
    hostname_str: "web-prod-node03"
    app_version: "3.10.2"
  tasks:
    - name: Ubuntu 24 전용 작업
      ansible.builtin.debug:
        msg: "Ubuntu 24 전용"
      when:
        - ansible_facts['distribution'] == "Ubuntu"
        - ansible_facts['distribution_major_version'] == "24"

    - name: Debian 12 전용 작업 (이 랩에서는 skip)
      ansible.builtin.debug:
        msg: "Debian 12 전용"
      when:
        - ansible_facts['distribution'] == "Debian"
        - ansible_facts['distribution_major_version'] == "12"

    - name: match 테스트
      ansible.builtin.debug:
        msg: "web- 로 시작한다"
      when: hostname_str is match("web-.*")

    - name: search 테스트
      ansible.builtin.debug:
        msg: "노드 번호 패턴이 어딘가에 있다"
      when: hostname_str is search("node[0-9]+")

    - name: version 테스트
      ansible.builtin.debug:
        msg: "app_version이 3.9 이상이다"
      when: app_version is version('3.9', '>=')

    - name: 존재하지 않는 파일 확인
      ansible.builtin.command: test -f /etc/does-not-exist-xyz
      register: r
      ignore_errors: true

    - name: is failed
      ansible.builtin.debug:
        msg: "failed 로 판정됨"
      when: r is failed

    - name: is succeeded (skip 예상)
      ansible.builtin.debug:
        msg: "succeeded 로 판정됨"
      when: r is succeeded
```

```bash
# ansible-ctrl에서 실행 (~/lab/ex06)
ansible-playbook conditions.yml
```

**2-5.** `conditions.yml`을 실행해 `skipping`으로 표시되는 작업과 `ok`로 표시되는 작업이 예상과 일치하는지 확인하세요.

**3-5.** 서로 다른 두 작업이 각각 다른 이름으로 같은 핸들러 묶음에 알림을 보내도록 `listen` 키워드를 사용한 `listen_cache.yml`을 작성해 실행해 보세요.

— `~/lab/ex06/listen_cache.yml`
```yaml
---
- name: Listen practice
  hosts: nodes
  tasks:
    - name: Deploy config X
      ansible.builtin.copy:
        dest: /tmp/ch06-x.conf
        content: "x=1\n"
        mode: '0644'
      notify: refresh cache

    - name: Deploy config Y
      ansible.builtin.copy:
        dest: /tmp/ch06-y.conf
        content: "y=2\n"
        mode: '0644'
      notify: refresh cache

  handlers:
    - name: Clear cache
      ansible.builtin.debug:
        msg: "cache cleared"
      listen: refresh cache
```

```bash

```

두 작업 모두 `refresh cache`라는 주제(listen)에 알림을 보내고, `Clear cache` 핸들러는 알림을 몇 번 받든 한 번만 실행됩니다.

**5-2.** 블록 안에 일부러 실패하는 작업(존재하지 않는 디렉터리를 확인하는 명령)을 추가하고, `rescue` 섹션에서 오류를 잡아 메시지를 출력하도록 작성하세요.

**5-3.** `always` 섹션을 추가해 성공/실패와 무관하게 항상 실행되는 작업을 만드세요.

**5-5.** `rescue` 섹션에서 복구한 뒤 핸들러를 강제로 실행해야 하는 상황을 가정해, `ansible.builtin.meta`로 `flush_handlers`를 호출하는 작업을 추가해 보세요.

— `~/lab/ex06/block_practice.yml`
```yaml
---
- name: Block practice
  hosts: ansible-node1
  tasks:
    - name: Grouped tasks
      block:
        - name: Create a ready marker
          ansible.builtin.file:
            path: /tmp/ch06-ready
            state: touch
            mode: '0644'

        - name: Show the marker
          ansible.builtin.command: ls -l /tmp/ch06-ready
          register: status
          changed_when: false

        - name: Print status
          ansible.builtin.debug:
            msg: "{{ status.stdout }}"
      when: ansible_facts['distribution'] == 'Ubuntu'
      become: true

    - name: Deploy check with rollback
      block:
        - name: Print a message
          ansible.builtin.debug:
            msg: '정상적으로 실행 중입니다'

        - name: Force a failure
          ansible.builtin.command: test -d /nonexistent-ch06-dir

        - name: Never print this
          ansible.builtin.debug:
            msg: '여기까지는 절대 오지 않습니다'
      rescue:
        - name: Print when errors
          ansible.builtin.debug:
            msg: '오류를 감지해서 복구 절차로 넘어왔습니다'
        - name: Flush handlers after recovery
          ansible.builtin.meta: flush_handlers
      always:
        - name: Always do this
          ansible.builtin.debug:
            msg: "성공하든 실패하든 이 작업은 항상 실행됩니다"
```

```bash
# ansible-ctrl에서 실행 (~/lab/ex06)
ansible-playbook block_practice.yml
```

**5-4.** `block_practice.yml`을 실행한 뒤 PLAY RECAP에서 `failed`와 `rescued` 값이 각각 몇으로 집계되는지 확인하세요.
